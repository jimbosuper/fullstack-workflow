# Agent 工作流

> **这是合订本备份：按「主要逻辑」拼回 7 份单文件，便于整体阅读。**
> 活版本是散在 `skills/`、`agents/`、`templates/` 里的那一套；**这 7 份是备份，不参与安装。**
> 两者内容必须一致：改了活版本，这里要跟着改；改了这里，活版本也要改。

给 OpenChamber 用的全栈交付规范。**核心是三阶段、四道门、六个停点、七个角色，外加一个只做大任务的主 agent。**

## 一、这套东西长什么样

**三个入口，级别由人选 agent 决定**：`build` 做小任务、`plan` + `build` 做中任务、`fullstack-workflow` 做大任务与做项目。

**一条大任务走三阶段、四道门、六个停点**，七个角色各写一个 `docs/` 目录，每个阶段审一次、人放行一次。

**`docs/` 的形态是「一个产物一个目录」**：`01-设计/01-设计系统/01-设计系统.md`。项目级不带版本与日期，链上带 `_v<版本>_<日期>`。

**需求先进 `02-产品/01-需求池/01-需求池清单.md`**，一条一行；立项的搬进 `04-PRD产品需求/` 并占用需求编号。**池子不占编号，进池也不代表会做。**

**门规则不在全局 `AGENTS.md` 里，只在主 agent 正文里。** 全局只留 9 节地板——安全、纪律、事实、交付、上下文；这样 `build` 修一个 bug 时读不到整套门规则。

## 二、装什么

| # | 文件 | 装到哪 | 内容 |
|---|---|---|---|
| 1 | `01-全局AGENTS模板.md` | `~/.config/opencode/AGENTS.md` | **9 节地板**：安全、纪律、事实、交付、上下文。**不含门规则** |
| 2 | `02-subagent模版.md` | 拆成 8 个文件进 `~/.config/opencode/agents/` | 1 个主 agent（`primary`）+ 7 个角色（`subagent`） |
| 3 | `03-skill与mcp模板.md` | 按表装配 | 每个角色用哪个 skill、连哪个 MCP |
| 4 | `04-项目AGENTS模板.md` | 每个项目复制成 `AGENTS.md` | 项目特有的事实与命令 |
| 5 | `05-docs文档模板.md` | 不装 | `docs/` 下每份产物写哪几节；每份第一节是「本文结论」 |
| 6 | `06-项目目录模板.md` | 不装 | 根目录 / `src/` / `test/` / `deploy/` / `docs/` 五棵树的形态。**只有目录，不写规则** |

**1–3 是全局的，装一次。4 每个项目装一次。5、6 是查用。**

## 三、三个入口：级别由人选 agent 决定

| 入口 | 级别 | 干什么 | 产物落哪 |
|---|---|---|---|
| `build`（内置） | 小 | 单文件、可一次回滚 | commit + 一句说明 |
| `plan` → `build`（内置） | 中 | 多文件、跨模块，但不动表结构 | plan 文件 + commit |
| **`fullstack-workflow`** | **大 / 做项目** | 三阶段、四道门、七个角色 | **整套 `docs/`** |

**级别不由模型判断，由人选哪个 agent 决定。** 「拿不准就升一级」会把所有小事升成大任务；选 agent 就没有这个模糊地带。

**选错了由人手动切走。** 不设自动降级；主 agent 唯一允许的例外动作是**拒收**：「这个适合 build / plan，请切换」。

**小任务和中任务不是不产出，是不落 `docs/`。** 中任务的方案在 plan 文件里，结果在 commit 里；`git log` 就是它的档案。

## 四、三阶段、三次审查、四道门六个停点

```text
阶段 1 · 设计与产品
  grill-me → 问清范围 →【停点 1】人确认范围 → 设计画原型（人提改到满意）
  →【停点 2】人确认原型 → 设计文档 → 产品文档
  → 审查 CR1 → 返修 →【门 1】人放行

阶段 2 · 架构与实现
  架构全套 → 架构自检 → 开发文档（TD）
  →【门 2A】人确认方案（代码未写）
  → 代码 → 自测 → 实现记录
  → 审查 CR2 → 返修 →【门 2B】人验收

阶段 3 · 验证与发布
  测试全套（含真跑）→ 运维全套
  → 审查 CR3 → 返修 →【门 3】人放行 → 上线
```

**四道门**：1 设计与产品 / 2A 方案（代码前）/ 2B 实现（CR2 后）/ 3 验证与发布。
**两个非门停点**：范围确认、原型确认——不写审查报告，但人不说过就不进下游。

**门后必须是机器无法代判的内容。** 审查能判「对不对」，判不了「是不是我们要的」。

**门不设代决**：人没说「过」，状态就是 `待确认`，不进下游。推断、沉默、「你觉得呢」都不算。

**六个停点意味着不能无人值守过夜跑**，也不设「预授权批量过门」。

## 五、七个角色，全派不挑

| 角色 | 写全哪个目录 | 为什么不能省 |
|---|---|---|
| 设计 | `01-设计/` | 原型由 OpenDesign 生成，但**验收、单文件校验、组件规范、页面规格都是它的活** |
| 产品 | `02-产品/` | 只读原型 + 派发问答，**不读设计文档**，保证 CR1 的交叉核对有效 |
| 架构 | `03-架构/` | 7 件产物；数据库设计里每张表都要写「与上游不一致处」；交活前要核 PRD 每条规则有没有落点 |
| 开发 | `04-开发/` + `src/` | TD 先落盘、过门 2A，才有第一个 commit |
| 测试 | `05-测试/` | 用例从 AC 反推，不是从代码反推 |
| 审查 | `07-审查/` | 每阶段一次，求差集，不复审 |
| 运维 | `06-运维/` | 交的文档是**人拿着去发布和回滚的**，不是给 AI 看的 |

**只有架构的「写多少」按需**：角色每次都派，但已有架构文档时只更新受影响的章节。

**主 agent 不写代码，但权限上不受限。**

| 项 | 事实 |
|---|---|
| 权限 | **没有路径禁区**。对所有目录与内容都能读写，方便干特别的事（一次性排查、改 `docs/` 结构、临时脚本） |
| 规范 | 项目代码仍只由开发子代理写；主 agent 自己动手等于绕过开发与 CR2，**必须在交付里写明为什么** |
| 部署 | 发布动作仍由人执行 |

**权限不设限是为了不被卡住；走不走流程靠规则和交付记录约束**——「能做」不等于「该做」。

## 六、三条内接缝

| 接缝 | 丢什么 | 补什么 |
|---|---|---|
| 设计 → 产品 | 产品会照着设计写需求，两个视角趋同 | **产品不读设计文档**，只读原型 + 派发问答 |
| 架构 → 开发 | TD 后补（实测代码早 52 分钟） | **TD 必须先落盘并经门 2A 放行**；判据是时间戳 |
| 测试 → 运维 | 运维不知道测试发现的脆弱点 | 运维读 TR，手册的「回滚」要对应 TR 里的风险项 |

## 七、审查怎么跑

**每个阶段一次，共 3 次。** 每次是一整套产物交叉核对，不是每个文件审一遍。

| 审查 | 核心工序 | 时间上限 |
|---|---|---|
| CR1 | 五道工序：PRD 说的页面 − 原型实际有 − 页面规格写了 → 差集 | 45 分钟 |
| CR2 | 规则链：PRD 规则 → 架构落点 → TD 路径 → 代码位置 | 60 分钟 |
| CR3 | AC 链：AC → TP 用例 → TR 结果 → 运维兜底 | 30 分钟 |

**差集才是主要产出。** 通读只能看出「写了什么」，看不出「缺了什么」。

**不复审**：每条 P0/P1 必须写成一条能跑的命令，作者改完自己跑，把输出贴进报告；人放行时只看有没有 🔴。

**自检表是入口**：作者交活前照 `docs/07-审查/01-审查清单/01-审查清单.md` 过一遍。**可发现且作者填了 ✅ 的占比 > 30% → 判「自检造假」，退回重写。**

## 八、装完怎么验

```bash
# 1. agent 应为 8（1 主 + 7 角色），primary 只能有一份
ls ~/.config/opencode/agents/ | wc -l
grep -l "^mode: primary" ~/.config/opencode/agents/*.md

# 2. skill 应为 8 个 workflow
ls ~/.agents/skills/ | grep -c workflow

# 3. 全局 AGENTS.md 应为 9 节，且搜不到门规则
grep -c "^## " ~/.config/opencode/AGENTS.md
grep -c "任务分级" ~/.config/opencode/AGENTS.md      # 必须为 0

# 4. 门规则在 agent 里
grep -c "四道门" ~/.config/opencode/agents/fullstack-workflow.md   # ≥ 1
```

**两条只能人验**：在那个主 agent 里说「改个错别字」→ 它应该拒收；说「做个 X」→ 它应该先调 `init-project` 建骨架，再问清范围。

## 九、卡住时

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 选不到主 agent | 文件没装或 `mode` 不是 `primary` | `grep -l "^mode: primary"` |
| 主 agent 自己把活干完了 | 它被装成了 `subagent` | 检查 frontmatter |
| 小改动也开三阶段 | 选错 agent | 手动切 `build`，这是设计行为不是 bug |
| 角色调不出来 | 该角色缺 `mode: subagent` | 检查 frontmatter |
| 一次派了多个角色 | 没读到「一次只派一个环节」 | 确认职责链 |
| OpenDesign 连不上 | daemon 没开或端口变了 | 重查端口改 `--daemon-url` |
| Archify 安装超时 | 没走代理，或源写成 `archify.si` | 导出 `https_proxy`；源写 `https://archify.si` |
| Archify 说图不好看但门都过了 | 有交叉连线没修 | 看 `visualReviewRecommendation` 调 `pos` 重跑 |
| 部署拓扑报 `deployment-private-state` | 数据库没放进 security-group | 每个环境一个私网安全组，包住应用 + 数据库 |
| ER 图报 `references unknown entity` | `references` 写成了表名 | 用 entity 的 `id` |
